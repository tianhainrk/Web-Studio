# Facebook Reels Studio — deployment

This module adds a Vietnamese dashboard at `/reels.html` without replacing the existing PineDrama/DramaBox catalog and Google Drive Manager.

## Architecture and account requirements

- **Vercel Hobby** serves the existing site plus authenticated `/api/reels/*` endpoints. HTTPS is mandatory.
- **Supabase** stores OAuth token ciphertext, enabled Pages, campaigns, scheduled jobs, and action history. Browser clients never receive the service-role key, page tokens, or Google refresh tokens.
- **Google OAuth** uses the `drive.file` scope. The app can only list Drive files accessible under that consent. The existing `PineDrama-Library/<collection-id>/EPxxx.mp4` folders must be visible to this Google OAuth client. If the folder isn't returned, open/create it using the *same* app's OAuth grant and Drive Manager.
- **Meta OAuth** connects Pages using `pages_show_list`, `pages_read_engagement`, and `pages_manage_posts`. Your Meta app needs appropriate Page tasks, permissions, and review/access level. Personal timelines are not supported.
- **GitHub Actions** runs every five minutes using `.github/workflows/reels-worker.yml`; schedules aren't exact-time guarantees. It takes the next due item and streams Drive video into Meta's official Reels upload endpoint. It never downloads entire MP4s into RAM.
- The uploader currently supports MP4s up to **512 MiB** per video to bound resource consumption. Video must meet Meta's Reels constraints (vertical video, aspect ratio, codec, duration). It does not transcode.
- The worker uses the Meta upload session -> local binary upload -> `finish PUBLISHED` flow, not native Meta pre-scheduling. Video publication is *requested* when the worker runs.
- Video needs to be licensed and authorized to post. The app does not extract locked or protected content.

## 1. Supabase

1. Create a Supabase project at https://supabase.com.
2. Open SQL Editor and run `supabase/reels.sql` **once**. This creates private tables and the atomic `claim_reel_jobs` RPC.
3. Copy Project URL and the **service_role** key from your project configuration. **Never** use the public anon key as the service role.
4. Do not add permissive RLS policies for the Reel tables. All app calls run from the server with the service role.

## 2. Vercel Environment Variables

Keep original settings (including `STUDIO_PASSWORD` 12+ characters and `SESSION_SECRET` 32+ characters).

| Variable | Source |
| --- | --- |
| `SUPABASE_URL` | Supabase Project URL |
| `SUPABASE_SERVICE_ROLE_KEY` | Supabase server-only service role key |
| `REELS_ENCRYPTION_KEY` | 32 random bytes in **64 hex characters**, generated by `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"` |
| `META_APP_ID` | Meta for Developers App ID |
| `META_APP_SECRET` | Meta for Developers App Secret |
| `GOOGLE_CLIENT_ID` | Google Cloud OAuth Web application |
| `GOOGLE_CLIENT_SECRET` | Google OAuth Web client secret |
| `GEMINI_API_KEY` | Gemini API key, optional |
| `GEMINI_MODEL` | Optional model, default `gemini-2.5-flash` |
| `MUSEAI_CAPTION_ENDPOINT`, `MUSEAI_API_KEY` | Optional. *Integration contract is unverified*: only use after your MuseAI provider confirms an authorized captions endpoint compatible with `{prompt}` request and `{caption}` response. |

**Google OAuth redirect URI**: `https://YOUR-VERCEL-DOMAIN/api/reels/oauth/google/callback`

**Meta Facebook Login redirect URI**: `https://YOUR-VERCEL-DOMAIN/api/reels/oauth/meta/callback`

Register the exact deployed domain and callback URIs in the providers' consoles. Google Cloud OAuth consent must include the Drive scope and test users while in Testing. The Meta App must be allowed to request the named Page permissions.

Redeploy after adding variables.

## 3. GitHub Actions secrets

Go to repository → Settings → Secrets and variables → Actions → New repository secret.

Configure these secrets with the **same** values set in Vercel:

`SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `REELS_ENCRYPTION_KEY`, `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`.

The GitHub Actions workflow only runs scheduled checks on the **default branch**. It can also be started manually through Actions → Process Facebook Reels Queue → Run workflow.

Vercel Hobby daily cron is insufficient for requested per-hour schedules; GitHub Actions is a best-effort 5-minute alternative, but GitHub may delay or skip scheduled events under load. Consider a persistent job service when exact-time or higher volume is required.

## 4. Operation

1. Sign in to PineDrama Studio normally.
2. Open `/reels.html` from the banner.
3. Connect Google OAuth, connect Meta OAuth, select the Page(s).
4. Load the `PineDrama-Library` folders. Select a series, then a set or range of `EPxxx.mp4` files.
5. Set campaign name, Page, Vietnam-local date/time, posts/day, spacing, and review the caption. Gemini can produce a draft for manual editing.
6. Create campaign. The server writes a persistent one-row-per-episode schedule in Supabase and prevents duplicates for the same Page + Drive file.
7. Monitor jobs. Only **queued** jobs can be canceled. In-progress tasks cannot be canceled remotely without risking a half-published video.
8. Reconcile Meta video status to confirm publishing; successful upload/finish alone is not proof that the Reel is live.
9. Inspect audit history within the dashboard. Failed transfers require manual investigation; they are not auto-retried to prevent accidental duplicate posts.

## Important limitations

- The original server-side `/api/transfer/start` queue from the preexisting project is in-memory, which is **not reliable on Vercel**. The new Supabase-backed Reels queue is separate.
- Meta access and Google refresh tokens are encrypted at rest with AES-256-GCM, but **rotating the encryption key without migrating saved ciphertext makes old OAuth connections unreadable**.
- The connection grant on `drive.file` only sees app-created/opened Drive files. If the existing Drive library was created with a different OAuth client, the user may need to reauthorize the same app or modify access strategy.
- MuseAI's particular caption API format has not been verified against a real provider and is not production-ready until that contract is validated. Gemini is implemented against Google's public generateContent API but requires your own key and quota.
- Facebook Page publishing must comply with content licenses, platform policies, valid token permissions, and approved app access.
- Rate limiting on the Studio login/API should be enabled via Vercel Firewall or a dedicated edge gateway.
- There is no live integration test against Meta, Drive, Supabase, or AI providers without your credentials. Unit and syntax tests do not prove end-to-end publication.

## Troubleshooting

- `/api/health` reports the existing login configuration. `/api/reels/config` lists booleans for Reels connection readiness after signing in.
- Supabase "relation not found": run `supabase/reels.sql` in the correct Supabase project.
- OAuth error: check HTTPS domain, callback allowlists, and credentials.
- Empty Drive list: verify the Google account, Drive API, and `drive.file` visibility.
- Worker error after job claim: inspect Actions run logs, Supabase `reel_jobs.error`, and `reel_audit`. Do not manually reset an already-started upload to queued before verifying Meta publication.
